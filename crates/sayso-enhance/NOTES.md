# sayso-enhance

`Enhancer` implementations for `sayso_core::enhance`. All calls block.

## API

- `build_enhancer(&Provider, &Arc<dyn SecretStore>, &Ai, Option<Arc<dyn LanguageModel>>) -> Box<dyn Enhancer>`. Never fails. A provider that cannot work (missing API key, missing binary, no ChatGPT sign-in) returns `NotConfigured` from `enhance`. The store is an `Arc` because the ChatGPT enhancer writes refreshed tokens back. `Ai` timeouts are the default for requests with a zero timeout.
- `SecretStore` with `KeychainStore` (service `dev.sayso.Sayso`) and `MemoryStore`.
- `OpenAiCompatible`: `POST {base_url}/chat/completions`. Mode ladder `json_schema`, `json_object`, `tool_call`. Next mode on HTTP 400/422 or a reply that does not match the schema. Working mode cached per `(base_url, model)` for the process (`clear_mode_cache()`). One whole-call deadline. OpenRouter extras: `provider.require_parameters` (json_schema and tool_call modes), `zdr` and `data_collection: "deny"` with `zero_data_retention`. Builder: `with_api_key`, `with_zero_data_retention`, `with_cloud`, `with_openrouter`, `with_default_timeout`.
- `ClaudeCli::new(id, path: Option<PathBuf>, model)`, `with_config_dir(Option<PathBuf>)`, `with_spare(bool)`. The stream-JSON protocol of the Agent SDK: `claude --input-format stream-json --output-format stream-json --verbose --await-initialize` with the model, effort, and the hygiene flags as arguments; then on stdin an `initialize` control request with `systemPrompt` and `jsonSchema`, and one user message with the tagged transcript. Reads `structured_output` of the `result` line. Fails on a refused `initialize` (login problems become `NotConfigured`), `is_error`, or a non-success `subtype`; a process that stops early reports the end of its stderr. `MAX_THINKING_TOKENS=0` at `low`, temp cwd, kill on timeout. One process serves one request.
- Spares: a request takes the started process of its binary, model, thinking level, and config folder (a spare) when one runs, and starts the next one in the background. A spare stops after `SPARE_LIFETIME` (10 min), and on its own when Sayso quits (its stdin closes). `prepare(&Provider)` starts one; the app calls it when the microphone opens. `stop_spares()` stops them all. Measured: 1.7 s for a cold request, 0.8 s from a spare (Haiku, tool 2.1.314).
- `ChatGpt::new(id, model: Option<String>, Arc<dyn SecretStore>)`, `with_thinking`, `with_default_timeout`. The ChatGPT plan through the Codex backend (`chatgpt.com/backend-api/codex`), with the OAuth client of the Codex CLI. Not a documented API for apps: OpenAI's "Sign in with ChatGPT" for open-source apps replaces it when Sayso can use it, and only `chatgpt.rs` knows the client and the backend. Tokens are one JSON item in the secret store under `chatgpt.<provider id>`. The access token is refreshed when it ends within 2 min, and once more when the backend answers 401; refreshes run one at a time because the refresh token rotates. A refresh that the server refuses (400/401) removes the sign-in. `POST /responses` streams (`store: false`, the style prompt in `instructions`, `text.format` json_schema, `reasoning.effort`; no `temperature` or `max_output_tokens`, which the backend refuses). With no model, it uses the first `mini` model of `GET /models`, else the first one, cached per account. The Codex CLI kind (`codex_cli`) is gone: the config turns its entries into this kind.
- `AcpAgent::new(&Provider, &dyn SecretStore)`, `with_default_timeout` (the CLI timeout from `Ai`). Any agent that speaks the Agent Client Protocol, version 1 (JSON-RPC 2.0, one message per line, on the agent's stdin and stdout), provider kind `acp` in `[[ai.agents]]`. Sayso is the client: `initialize` (no file or terminal capabilities), then `session/new` in an empty temp folder with no MCP servers for each request, `session/set_config_option` (the `model` category) or the older `session/set_model` (agents that send `models`), one `session/prompt` with the style prompt, the reply rules and the tagged transcript in one text block (ACP has no system prompt), the `agent_message_chunk` text joined, then `session/close` when the agent has it (not awaited). Stop reasons: `end_turn` ok, `refusal` is `Refused`, `max_tokens` and `max_turn_requests` are `InvalidOutput`. Error `-32000` (auth required) and login-like messages are `NotConfigured("not signed in to <agent>: ...")`. At the deadline Sayso sends `session/cancel`, gives `Timeout`, and stops the agent. Requests of the agent: `session/request_permission` gets a reject option, else `cancelled`; everything else (`fs/*`, `terminal/*`, unknown) gets `-32601`. Mode `acp`, `report.run_ms` is the prompt turn. Secret variables are in the secret store under `acp_secret_account(id, NAME)` (`acp.<id>.<NAME>`); a missing one is `NotConfigured`.
- ACP agent pool: one started, initialized agent per provider id, keyed by a hash of the command, arguments and environment (a change starts a new agent). `keep_running` (default true) keeps it; a reaper stops it after `ACP_IDLE_LIMIT` (10 min) without use, and stops dead ones. `keep_running = false` starts it for each call and stops it after. An agent in the pool that died is started again once per request; one that timed out is stopped. Stop: close its input, wait 1 s, kill (an `npx` agent is a child of `npx` and exits when its input closes). The agent starts through `cli::spawn` (Flatpak host, Windows shims). A bare command is searched in `PATH`, the usual folders, then nvm (newest) and volta; the folder of the program goes first in its `PATH`, because `npx` needs `node` and a Dock launch has a short `PATH`. Its error output is kept (last 4 KB) and added to the error of an agent that stopped. `stop_acp_agent(id)`.
- ACP `auth_status`: start or reuse the agent and open a session: ok is `SignedIn { account: None }`, auth required is `SignedOut`, a missing command is `NotInstalled`, a timeout or other error is `Unknown`. `SignIn::start` initializes the agent (up to 60 s, blocking) and sends `authenticate` for its first `agent` method; `opens_browser()` is true; `next_event()` gives `Finished(status)` only; `cancel` stops the wait and the agent. An agent with only terminal methods (`type: "terminal"`, or the older `_meta["terminal-auth"]`) gives `NotConfigured` with the command to run.
- `check_agent(command, &[String], &BTreeMap env, timeout) -> AgentCheck { name, version, protocol_version, auth_methods, signed_in, models }` for the "Add your own agent" form. Starts the agent outside the pool and stops it. A protocol version other than 1 is `NotConfigured`.
- ACP models (`list_provider_models`): the models of a new session, in the agent's order (flat or grouped options). Thinking levels only on the current model, from the `thought_level` config option, without `default`; other models may have other levels, so they get none.
- `registry`: `fetch_registry(cache_path, timeout)` (the CDN file, saved to the cache; the cache when offline), `cached_registry`, `parse_registry` (a bad entry is skipped), `current_platform()` (`darwin-aarch64`, ...), `resolve_launch(&agent, install_root) -> Launch { command, args, env }` (installed download, then `npx -y <package> <args>`, then `uvx <package> <args>`; `NotConfigured` when the download is not installed or the tool is missing), `install_binary(&agent, install_root, timeout)` (into `<root>/<id>/<version>`, SHA-256 checked when the registry gives one, `.tar.gz`/`.tgz`/`.tar.bz2`/`.tar`/`.zip` or a bare program, made executable, program path kept inside the folder), `installed_binary`, `local_command(id)` (the agent's own command when it is on this computer: `opencode acp`, `gemini --acp`, `cursor-agent acp`).
- `EngineModel::new(id, Option<Arc<dyn LanguageModel>>)`: the language model that the engine runs on this computer (Apple Intelligence on macOS, provider kind `apple_intelligence`). It sends the style prompt as instructions and the tagged transcript as the prompt, then applies the same checks to the text as the other providers. Not cloud. Without an engine it returns `NotConfigured`. This crate does not depend on the engine client: the app passes the handle in.
- Config folder: `config_dir` of the Claude CLI provider sets `CLAUDE_CONFIG_DIR` for every run of the tool (enhance, model list, status, sign-in). A leading `~/` is the home folder (`HOME`, `USERPROFILE` on Windows). Unset leaves the environment as it was. One helper in `auth.rs` does the env name and the expansion.
- `auth_status(&Provider, &dyn SecretStore, timeout) -> Option<AuthStatus>`: `claude auth status` (JSON on stdout), or the saved ChatGPT sign-in (signed in while tokens are saved; the label is the plan and the email of the ID token). None for kinds without a login. A configured folder that does not exist gives `SignedOut` without running the tool. Binary not found gives `NotInstalled`. A failed or unreadable status gives `Unknown`.
- `SignIn::start(&Provider, Arc<dyn SecretStore>)`: `claude auth login` (stdin piped, `takes_code()` true), or the ChatGPT sign-in: PKCE, a callback server on `127.0.0.1:1455` (else 1457; a server that holds the port is asked to `/cancel` once), the code exchanged for tokens, which are saved. `opens_browser()` is false for ChatGPT: the caller opens the `Url`. A callback with another `state` is refused and the sign-in waits on. `chatgpt_sign_out(&dyn SecretStore, id)` removes the tokens. The CLI sign-in creates the config folder. Both output pipes are read by helper threads. `next_event()` gives one `Url` (first http(s) token), then `Finished(AuthStatus)` once; the status is read again with `auth_status` (10 s). `send_code`, `cancel`. The limit is `SIGN_IN_LIMIT` (10 min); `start_with_limit` (hidden) is for tests. `Send + Sync`. Drop kills and waits for the tool.
- Detection: `detect_claude_cli`, `detect_ollama(timeout)`, `detect_ollama_at(url, timeout)`, `list_models(base_url, key)`, `test_provider(&dyn Enhancer)`.

The live registry parses (44 agents, 22 with a download for this Mac).
Unit tests: request bodies, reply parsing, envelope parsing, executable search, factory.

## Not tested

ACP: a real `authenticate` (opencode's only method is of the `agent` kind but says to run `opencode auth login` in a terminal; nothing was signed in or out), a real download from the registry (the install ran against a local server), `uvx` agents, Windows and Flatpak launches of agents, agents that still send `models` (only the fake), an agent that sends `config_option_update` during a turn, `session/close` against a real agent beyond "no error". The agents' own tools: Sayso refuses the permission requests, but an agent whose own settings allow a tool (opencode's `build` mode, Claude's `auto` mode from the user's settings) may run it without asking, in the empty folder. Agents are not stopped when Sayso quits; they exit when their input closes. The real `claude auth login` (it opens a browser; only the status command ran by hand), the real ChatGPT sign-in and backend (the request follows the Codex CLI source and other open-source clients, but no real call was made), the Flatpak path of the config folder (no existence check, no folder creation), the Windows path, Real providers, the real `claude` command (the `claude -p` stdin input follows the CLI help and docs, but no model call was made), `KeychainStore` (it would prompt for Keychain access), HTTPS and TLS, streaming.
